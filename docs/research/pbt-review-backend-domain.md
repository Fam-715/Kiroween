**Unclear or missing**
- **Frontend mirror:** `frontend/src/domain/strength.ts` and `frontend/tests/` don't exist. When they do, add a fast-check cross-check against the backend for `strengthAt`, `condition`, `isDue`, `nextReviewAt` and `tapeStrength`. It needs shared golden vectors or generated fixtures.
- **Penalty scope:** Requirement 4 says penalties apply "only to tracks completed in the session", and event IDs must be idempotent. Neither rule lives in these two files. Where the session logic sits is not defined here, so I can't suggest a target.
- **Capacity message:** Requirement 2.4 says to show the remaining minutes. `validate_side` reports "over capacity by N minutes", which is the overage, not the remaining time. The spec doesn't say which is intended, so I can't state a property for the message.
- **Whitespace handling:** The title, name and key-term checks mix stripped and unstripped lengths. For example, `len(title) > 60` is unstripped but the minimum check is stripped. Duplicate detection strips and casefolds. The requirements don't say whether input is trimmed, so the length-boundary properties above need that decision.
- **Case folding:** `key_terms_unique` uses `casefold()`, and scoring uses lowercasing. The spec says only "ignoring case". Unicode cases such as `ß` and `SS` are undefined, so I limited the suggestions to ASCII.
- **`review` with `now` before `last_reviewed_at`:** Code treats Δ as 0, which gives a ratio of 1 and blocks the stability rise. The spec says Δ is never negative but gives no `review` behaviour for this case.
- **`last_reviewed_at is None` with `review_count > 0`:** The state is not defined. The existing `memories()` strategy never generates it.
- **Float scores near .5:** `round_half_up(score * 100)` can be float-sensitive for arbitrary floats. Real scores are `matched/total` with total 3–5, so an exact .5 never occurs. The spec doesn't say whether `review` should accept arbitrary floats or only `k/n`.
- **Unchanged tracks:** The domain only receives `unchanged_ids`. "Same id and same minutes" is decided by the caller, so that rule can't be tested at this layer.
